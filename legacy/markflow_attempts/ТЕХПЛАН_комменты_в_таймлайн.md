# Техплан: «Комменты сценария → таймлайн Premiere» (канал Макашенец)

**Для кого:** разработчик (человек или сессия Claude Code в облаке).
**Главное условие:** лимиты почти на нуле, поэтому 95% разработки и все тесты идут в облаке, без Premiere и без компа Артёма. На ноутбук выходим один раз, в самом конце, на дымовой прогон.

---

## 0. Коротко для Артёма (без терминов)

Мы строим «переводчик»: он берёт сценарий с комментариями и выдаёт **план раскладки**. В плане для каждого коммента записано, куда он встаёт по времени, что по нему скачать и что с ним делать: поставить само, сделать текстовым слоем или оставить маркером.

План — это обычный файл, и проверять его можно где угодно. Поэтому почти всё проверяем в облаке на твоих старых роликах: «Дудь/Морген», «Модная пропаганда», «Ландыши 2». Premiere нужен только на последнем шаге, когда план превращается в реальный таймлайн.

## 2. Архитектура: чистое ядро + тонкие адаптеры

```
            ┌──────────── облако, всё тестируется ────────────┐
docx ─► [parse_doc] ─► [parse_comment] ─► [classify] ─┐
                                                      ├─► [build_plan] ─► edit_plan.json + отчёт.md
transcript (csv/json/srt/words.json) ─► [align] ──────┘
            └─────────────────────────────────────────────────┘
edit_plan.json ─► [robot_jobs]      ─► очередь робота (скачивание)     ← комп Артёма
edit_plan.json ─► [premiere_apply]  ─► маркеры / вставки / текст       ← комп Артёма
```

Правило: **ни один модуль ядра не ходит в сеть, в Premiere или на диск Артёма.** Весь ввод-вывод идёт через адаптеры с интерфейсом, и в тестах их заменяют подделки.

### Модули ядра (Python 3.11, только stdlib + `rapidfuzz`, `pydantic`)

1. **`parse_doc`** — docx → список `Anchor{comment_id, anchored_text, paragraph_idx, context_before, context_after}` и `Comment{id, author, text, links[]}`.
   - Ссылки брать и из текста коммента, и из `w:hyperlink` в `document.xml` через `_rels`.
   - Если коммент стоит на пустом выделении, `anchored_text` — ближайший абзац, с флагом `anchor_weak=true`.
2. **`parse_comment`** — текст коммента → `{urls[], source_timecodes[], filenames[], hints[]}`.
   - Разлеплять склеенные ссылки (`…/ZN8Y2d2BK/https://…`).
   - Таймкод у ссылки: хвост `:19:55`, `?t=`, `&t=1m20s`, а также отдельно стоящий `4:02:40`.
   - Имена файлов: `\S+\.(mp4|mov|png|jpg|wav|mp3|…)`.
   - Подсказки по словам: `ВИДЕО`, `коллаж`, `скрин`, `плашка`, `цитата`, `титр`, `звук`.
3. **`classify`** → одно из трёх:
   - `AUTO_MEDIA` — есть скачиваемая ссылка (YouTube, TikTok, Instagram, ok.ru, VK, Telegram, rutube, прямая картинка или видео) либо найден файл по имени;
   - `TEXT_LAYER` — плашка, цитата, титр, ссылка на статью или текст песни;
   - `MARKER_ONLY` — всё творческое или непонятное.
   - Звук ставится `AUTO` **только** если файл назван явно и найден в `БАЗА/SFX_*`. Иначе `MARKER_ONLY`.
   - Сомнение → `MARKER_ONLY`. Лишний маркер дешевле, чем ошибочная вставка.
4. **`align`** — `anchored_text` → `{t_start, t_end, confidence}` по расшифровке.
   - Ведущий говорит не слово в слово по сценарию, поэтому: нормализация (регистр, ё/е, пунктуация, числа прописью ↔ цифрами), затем скользящее окно по словам и `rapidfuzz.partial_ratio`.
   - Монотонность: комменты идут по сценарию, значит время не должно убывать. Выбросы переставлять через DP или LIS и помечать.
   - Порог: `confidence < 0.6` → `NOT_FOUND`, коммент уходит в отчёт, в план не попадает.
   - Входы: CSV Premiere (`;`-таймкоды, drop-frame 29.97), `.words.json` робота (`w/s/e`), SRT.
5. **`build_plan`** → `edit_plan.json` (контракт ниже) + человекочитаемый `отчёт.md`: что поставлено, что не найдено, что уйдёт на скачивание.
6. **`robot_jobs`** → JSON-задания в формате робота шортсов: `{"type":"download","url":…,"folder":…,"height":1080}`. Имя файла: `NNN_<домен>_<слаг>.ext`, где `NNN` — порядковый номер коммента по сценарию (как в `cut_manifest.json`).
7. **`premiere_apply`** (адаптер, только на ноутбуке) — план → вызовы Premiere: маркер с полным текстом коммента, ссылкой, именем файла и фразой-якорем; вставка на дорожку V3+; текстовый слой или MOGRT.

### Контракт `edit_plan.json` (зафиксировать первым, pydantic-схема)

  "schema": 1,

      "n": 3,
      "comment_id": "5",

## 3. Тесты: всё в облаке, без сети и без Premiere

### 3.1 Фикстуры
- Скопировать в `tests/fixtures/` из папки Макашенца: 3 docx «Дудь/Морген», `cut_manifest.json`, обе XML-сборки, CSV/JSON «Модной пропаганды», `пропаганда расшифровки.docx`. Видео **не копировать**.
- Размеры известны и маленькие (docx ≈ 40 КБ, CSV ≈ 94 КБ). Самый тяжёлый — `…B0002.xml` на 2 МБ, это нормально.
- **Репозиторий только приватный**: это материалы клиента.

### 3.2 Уровни тестов

| Уровень | Что | Как проверяем |
|---|---|---|
| Юнит `parse_comment` | Все 12 реальных комментов из «Дудь/Морген» + синтетика | Табличные тесты: вход → ожидаемые `urls/timecodes/hints`. Склеенные ссылки, `:19:55`, `4:02:40`, пустой коммент, эмодзи, кириллица в ссылке |
| Юнит `parse_doc` | docx с комментами | Число комментов = 12, у каждого непустой якорь, ссылки из `w:hyperlink` не теряются |
| Юнит таймкодов | `00;00;22;04` ↔ секунды, DF/NDF, 25/29.97/30 | Проверка «туда и обратно» на 10 000 случайных значений (hypothesis) |
| Юнит `classify` | Каждый тип ссылки и каждая подсказка | Таблица ожиданий. Отдельный тест: «звук без явного файла → MARKER_ONLY» |
| `align`, устойчивость | Реальная расшифровка «Модной пропаганды» | Берём реальную фразу, **портим её** (выкинуть 20% слов, переставить 2 слова, цифры ↔ прописью, ошибка распознавания) — должна найтись ±1 с. Фраза, которой нет, должна дать `NOT_FOUND`, а не ложное попадание |
| `align`, монотонность | Порядок комментов | Если вручную «перепутать» порядок, выброс помечается warning |
| **Золотой тест, главный** | Докс «Дудь/Морген» → план | Сверка с тем, что реально стояло в `…_финал.xml` и `cut_manifest.json`: доля комментов, попавших в ±3 с от реальной вставки. Цель ≥ 80%. Какая расшифровка есть для этого ролика, выяснить (см. §6) |
| Снимок плана | `edit_plan.json` | Снимок-тест (syrupy): любое изменение раскладки видно в диффе |
| Контракт | `edit_plan.json` по схеме | pydantic-валидация. Отдельный тест: старая схема падает с понятной ошибкой |
| `robot_jobs` | Задания робота | Совпадение с форматом, который уже принимает `robot.ps1`. Имена уникальны, без запрещённых в Windows символов, длина ≤ 120 |
| `premiere_apply` с подделкой | Адаптер Premiere | Подделка записывает вызовы (`add_marker`, `overwrite_clip`, …) в список. Проверяем порядок, дорожки, отсутствие наложений, отсутствие ripple |
| Отказы | Битый docx, пустая расшифровка, 0 комментов, 300 комментов | Нет падений, понятный отчёт |

### 3.3 Правила
- В тестах сеть запрещена (`pytest-socket`). Все URL классифицируются офлайн.
- Один прогон: `pytest -q` меньше 30 с.
- Проверки на каждый коммит (GitHub Actions, ubuntu): `ruff` + `pytest`.
- Каждый баг, найденный на живом прогоне, сначала становится тестом-фикстурой и только потом чинится.

## 5. Что известно про Premiere (из прошлых сессий, учесть в `premiere_apply`)

- `insert_clip` и `apply_edit_plan` игнорируют in/out и дают ripple. **Не использовать.**
- Рабочий способ: `create_subclip(in, out)` → `overwrite_clip(start_seconds, track_index, audio_track_index)`.
- После каждой пачки — `get_sequence_structure` для проверки.
- Удалить дорожку субтитров инструменты не умеют.
- Кириллица в путях ломала старые ExtendScript-скрипты. Адаптер тестировать на путях вида `C:\Users\Artem\Videos\Макашенец\…`.
- Работать **только на копии проекта** (`… - Copy.prproj`), оригинал не трогать.

## 6. Открытые вопросы (закрыть по ходу, не блокируют этапы 1–3)

1. **Источник докса в бою.** Коннектор Google Drive умеет читать док с комментами (`read_file_content`, `includeComments`), но в его описании сказано, что формат текста может меняться. Поэтому основной вход — **docx-экспорт** (стабильный формат, на нём все тесты), а коннектор — только чтобы скачать этот docx. Проверить одним вызовом на живом доке.
2. **Решённые комменты.** В docx «Дудь/Морген» нет `commentsExtended.xml`, то есть статус «решён» в экспорте, похоже, не виден. Уточнить: пропускать решённые или нет.
3. **Расшифровка для золотого теста.** Для «Дудь/Морген» в папке видны сценарий и XML-сборки, CSV-расшифровка есть только у «Модной пропаганды». Либо взять расшифровку из XML или сделать роботом (один прогон на ноутбуке), либо золотой тест делать на «Модной пропаганде», если у неё найдётся сценарий-docx с комментами.
4. **Коллаж.** Ставить ли коллаж автоматически (сетка 2×2 или 3×1) или только класть файлы рядом и ставить маркер. По умолчанию — маркер.
5. **Таймкод из коммента** (`4:02:40`) — это точка в исходнике по ссылке. Подтвердить, что так везде.

## 7. Экономия лимитов — правила для разработчика

- Рутинный код и тесты писать моделью подешевле (Sonnet). Opus звать только на `align` и разбор спорных провалов золотого теста.
- Не гонять большие файлы через чат: фикстуры лежат в репо, модель читает их кодом, а не глазами.
- Видео в облако не тащить никогда. Всё тяжёлое (скачивание, распознавание) делает робот на ноутбуке бесплатно.
- На ноутбук выходить пачкой, а не по одному вызову.
